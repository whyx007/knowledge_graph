# 细粒度图谱模型

## 1. 设计目标

新版模型解决两个问题：

1. 产业链上下游粒度不够。
2. 新增产业链不应作为既有产业链的补充，而应平级管理。

## 2. 核心层级

```text
IndustryDomain
-> IndustryChain
-> ChainSegment
-> ChainStage
-> ChainSubstage
-> Enterprise
```

说明：

- `IndustryDomain`：产业大类，如光电子、商业航天。
- `IndustryChain`：具体产业链，如光通信/光模块、光学检测/机器视觉。
- `ChainSegment`：上游、中游、下游。
- `ChainStage`：一级环节，如光芯片、光模块、数据中心光互联设备。
- `ChainSubstage`：二级细分环节，如硅光芯片、800G光模块、AI集群互联。
- `Enterprise`：企业。

## 3. 节点类型

### IndustryDomain

字段：

- `domain_id`
- `domain_name`
- `description`

### IndustryChain

字段：

- `chain_id`
- `chain_name`
- `domain_id`
- `maturity_level`
- `pilot_flag`
- `description`

`pilot_flag=true` 只表示当前优先验证，不表示层级更高。

### ChainSegment

字段：

- `segment_id`
- `chain_id`
- `segment_name`
- `segment_order`

标准值：

- 上游
- 中游
- 下游

### ChainStage

字段：

- `stage_id`
- `chain_id`
- `segment_id`
- `stage_name`
- `stage_order`
- `definition`
- `include_criteria`
- `exclude_criteria`
- `keywords`

### ChainSubstage

字段：

- `substage_id`
- `stage_id`
- `substage_name`
- `definition`
- `keywords`

### Enterprise

字段沿用企业图谱主数据，但需要新增：

- `source_system`
- `source_pk`
- `last_sync_at`

## 4. 关系类型

```text
(IndustryDomain)-[:HAS_CHAIN]->(IndustryChain)
(IndustryChain)-[:HAS_SEGMENT]->(ChainSegment)
(ChainSegment)-[:HAS_STAGE]->(ChainStage)
(ChainStage)-[:HAS_SUBSTAGE]->(ChainSubstage)
(ChainStage)-[:UPSTREAM_OF]->(ChainStage)
(ChainSubstage)-[:UPSTREAM_OF]->(ChainSubstage)
(Enterprise)-[:LOCATED_IN_STAGE]->(ChainStage)
(Enterprise)-[:LOCATED_IN_SUBSTAGE]->(ChainSubstage)
```

企业挂接关系字段：

- `confidence`
- `evidence`
- `source_field`
- `source_system`
- `needs_review`

## 5. 平级产业链原则

所有产业链都进入 `IndustryChain` 节点表。

光通信/光模块只作为首个试点：

- 可以先有更完整的二级细分环节。
- 不拥有其他产业链。
- 不作为其他产业链的补充分类。

后续扩展时，其他产业链按同一模型补齐自己的 `ChainSegment`、`ChainStage`、`ChainSubstage`。
