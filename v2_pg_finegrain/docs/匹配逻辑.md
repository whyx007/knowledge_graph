# 被投企业合作匹配引擎：通用逻辑

## 1. 问题定义

> 给定一个**目标企业**（可能在或不在知识图谱中），找出图谱中能与之**合作**的被投企业，并按优先级输出匹配结果与合作路径。

**输入**：目标企业名称 + 可选辅助信息（行业、城市、业务描述）
**输出**：P0 / P1 / P2 三级匹配列表 + 合作路径建议

---

## 2. 数据源

| 数据源 | 存储 | 提供什么 |
|---|---|---|
| PostgreSQL（companies 表） | `is_invested = true` | 判定"是否被投"，提供企业业务字段 |
| Neo4j 知识图谱 | Enterprise 节点 + `LOCATED_IN_SUBSTAGE` | 提供企业画像和产业链位置 |

两个数据源通过 **企业名称** 做交集。交集部分数据最全，仅在一侧存在的企业标注为"数据缺失"。

---

## 3. 匹配流水线（6 步，与行业无关）

### Step 1：构建目标企业画像

无论目标企业在不在库里，先搞清楚它"是什么"。

```
IF 目标在 PG 中有记录:
    直接读取 industry / core_tech / products / scenario
ELSE:
    通过 web 搜索 + 用户提供描述 拼接画像
```

画像结构：

```python
target = {
    "name": str,          # 企业名
    "domain": str,        # 所处大领域（如"商业航天""半导体""新能源"）
    "city": str,          # 所在城市（用于地理邻近评分）
    "mode": str,          # 商业模式：整机集成商 / 核心零部件商 / 技术平台 / 服务商
    "needs": [str, ...],  # 核心需求关键词（需要什么配套）
    "desc": str,          # 自由文本描述（fallback 匹配用）
}
```

领域和需求关键词是驱动后续匹配的核心信号。

### Step 2：领域 → 行业关键词映射

将目标企业的**领域**映射为 PG 中用于筛选的行业关键词。这一步是泛化的关键——换领域只需维护此映射表。

```python
# 领域 → PG industry 字段的关键词（用 ILIKE 匹配）
DOMAIN_KEYWORDS = {
    "半导体":    ["半导体", "集成电路", "芯片", "晶圆", "先进封装"],
    "新能源":    ["新能源", "光伏", "储能", "动力电池", "锂电"],
    "低空经济":  ["无人机", "eVTOL", "低空", "通用航空"],
    "机器人":    ["机器人", "具身智能", "协作机器人"],
    "军工":      ["军工", "武器装备", "雷达", "导弹"],
    # ... 按需扩展
}
```

同时，每个领域预设一组"需求关键词"，用于 Step 5 的评分环节：

```python
DOMAIN_NEEDS = {
    "半导体":    ["晶圆制造", "封装测试", "设备零部件", "材料", "EDA"],
    "新能源":    ["电池材料", "BMS", "热管理", "逆变器"],
    # ...
}
```

### Step 3：从 PG 筛选被投企业

```sql
SELECT name, industry, core_tech, products, scenario, city
FROM companies
WHERE is_invested = true
  AND (
    industry ILIKE '%关键词A%'
    OR industry ILIKE '%关键词B%'
    OR ...
  )
```

这一步只做**粗筛**——用行业关键词在 `is_invested=true` 的池子里捞候选。宁可多捞不漏掉。

### Step 4：跟 Neo4j 交叉匹配

将 Step 3 的候选企业名与 Neo4j Enterprise 节点做交集：

- **PG ∩ Neo4j** → 有完整数据的匹配候选（进入 Step 5 评分）
- **仅 PG** → 被投但 Neo4j 无数据（标记为"需另行调研"）
- **仅 Neo4j** → 非被投企业（排除，不作为本次输出）

从 Neo4j 捞取的字段：

```
企业技术/产品属性 | 挂载二级环节 | 所属产业链
```

### Step 5：多维度评分

对每一条 PG ∩ Neo4j 的企业，做 5 个维度的加权评分。

#### 评分维度

| 维度 | 默认权重 | 计算方法 | 说明 |
|---|---|---|---|
| **业务相关性** | 40% | 企业文本字段中命中目标需求关键词的比例 | 核心维度，越高越直接匹配 |
| **产业链位置** | 25% | 判断目标企业的模式与该企业的供需关系 | 整机商→找有产品的供应商；零部件商→找互补技术 |
| **地理邻近** | 15% | 城市匹配（同城满分，同省半分） | 降低物流与协作成本 |
| **技术稀缺性** | 10% | 检测企业描述中是否含"独家/国内唯一/首款"等标志词 | 识别不可替代的标的 |
| **数据完整度** | 10% | 统计企业拥有的字段数 / 总字段数 | 数据越全，置信度越高 |

#### 计算公式

```
score = 0.40 × relevance + 0.25 × chain_position + 0.15 × proximity + 0.10 × uniqueness + 0.10 × completeness
```

#### 分级阈值

| 级别 | 默认阈值 | 含义 |
|---|---|---|
| 🔴 **P0** | ≥ 0.55 | 核心战略合作 — 直接配套或技术互补 |
| 🟡 **P1** | ≥ 0.40 | 关键配套 — 材料/部件/检测/服务 |
| 🟢 **P2** | < 0.40 | 潜力合作 — 弱相关，可关注 |

> 阈值可按行业特点调整。高集中度行业（如商业航天）阈值可上浮，分散行业（如新材料）可下调。

### Step 6：生成合作路径

不只看单个企业，把 P0+P1 的组合打包成可执行方案。

**路径生成规则**：

1. **核心需求覆盖路径** — 取每个需求方向 Top-N，确保关键环节不缺失
2. **本地产业链闭环** — 同城企业打包，降低物流和协作成本
3. **技术栈互补路径** — 将互补技术的企业组合（如："通信+存储+电源"打包成卫星互联网技术栈）

---

## 4. 泛化设计原则

### 换领域只需改两处

| 改动点 | 位置 | 内容 |
|---|---|---|
| 领域→行业关键词映射 | `DOMAIN_KEYWORDS` 字典 | 添加新领域及其对应的 PG industry 关键词 |
| 领域→需求关键词映射 | `DOMAIN_NEEDS` 字典 | 添加新领域常见配套需求关键词 |

其他所有逻辑（PG 查询、Neo4j 交叉、评分、路径生成）**与行业无关**。

### 目标企业模式→产业链匹配规则

不同商业模式下，"合作"的含义不同：

| 目标企业模式 | 匹配倾向 | 例 |
|---|---|---|
| **整机集成商** | 找有具体产品/能力的上游供应商 | 卫星总体 → 找卫星部组件/材料企业 |
| **核心零部件商** | 找下游集成商或互补技术供应商 | MCU 芯片商 → 找汽车 Tier1 / 互补传感器 |
| **技术平台** | 找可落地的应用场景方 | AI 平台 → 找有行业场景的集成商 |
| **服务商** | 找需要该服务的客户 | 检测服务商 → 找需要检测的制造企业 |

### 评分权重的可调性

所有 5 个维度的权重都是可配置的。不同场景下调整示例：

| 场景 | 建议调整 |
|---|---|
| 目标企业所在行业高度地域集中（如西安航天） | 提高地理邻近权重到 20% |
| 目标企业已有明确供应商体系 | 降低产业链位置权重，提高业务相关性 |
| 优先寻找稀缺技术 | 提高技术稀缺性到 20%，降低地理邻近 |
| 数据质量较差时 | 提高数据完整度权重到 15%，宁缺毋滥 |

## 5. 输出格式

```json
{
  "profile": { "name": "...", "domain": "...", "needs": [...] },
  "matches": [
    {
      "name": "企业名",
      "score": 0.65,
      "tier": "P0",
      "rationale": "高业务相关性; 同城(西安); 技术稀缺(国内唯一)",
      "capabilities": ["能力1", "能力2"],
      "products": ["产品1"]
    }
  ],
  "pg_only": [{ "name": "...", "note": "被投但 Neo4j 无数据" }],
  "pathways": [
    {
      "name": "合作路径名",
      "companies": ["企业1", "企业2"],
      "rationale": "组合理由"
    }
  ]
}
```

---

## 6. 局限性

1. **纯文本关键词匹配，不理解语义** — "航天电源"和"卫星电池"在语义上是相关的，但关键词匹配可能漏掉。如需更高精度，可引入 embedding 向量相似度。
2. **评分权重是经验值** — 不同行业的最优权重不同，建议在实际使用中积累 feedback 做参数调优。
3. **Neo4j 挂载覆盖率不完整** — 企业节点已同步，但部分企业尚无产业链挂载，需要继续补充和复核。
4. **领域关键词映射表需维护** — 当 PG 中 industry 字段出现新术语时，需更新 `DOMAIN_KEYWORDS`。
5. **地理信息依赖 PG city 字段** — 如果 city 为空或格式不统一，地理邻近评分会失效。
