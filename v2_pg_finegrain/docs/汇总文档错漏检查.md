# 汇总文档错漏检查

> 检查对象：`多产业链企业挂载环节与依据汇总.md`
> 对比基准：Neo4j 图谱 + PostgreSQL 数据库 + 原始分链文档 + 合理性分析

---

## ❌ 硬伤（需立即修复）

### 1. 光通信链：英伟芯 → 硅光芯片 缺失

**问题**：Neo4j 中英伟芯 (ENT_PG_63) 已挂载到 `SUB_OC_004 硅光芯片`，且 PostgreSQL 明确记载"异质集成硅光技术"、"晶圆级混合集成工艺"。但汇总文档光通信链中，英伟芯仅出现在 CPO/光电共封装（CPO引擎、光I/O），**没有硅光芯片挂载**。

**影响**：光通信链挂载关系数少算 1 条（当前 31 → 应为 32），硅光芯片环节少了一家核心企业。

**修复**：在光通信→光芯片→硅光芯片下增加：
```
ENT_PG_63 | 英伟芯（西安）科技有限公司 | 光芯片 | SUB_OC_004 | 硅光芯片 | medium | false | 异质集成硅光技术，晶圆级混合集成工艺
```

## ⚠️ 需商榷（建议调整）

### 2. 光计算链：九章量子 → 数据中心光计算方案 (SUB_COMP_024) 不合适

**问题**：九章（济南）量子科技是**光量子计算原型机**（学术标杆，"九章"/"九章二号"），但被挂到"数据中心光计算方案"（SUB_COMP_024），概念偏差大——量子计算机 ≠ 数据中心解决方案。

**当前链中无专门光量子计算环节**。SUB_COMP_024 的描述是"面向数据中心的光计算解决方案"，与量子学术计算场景不匹配。

**建议**：
- 方案 A：在光计算链中新增 `SUB_COMP_xxx 光量子计算平台`，将九章量子、本源量子、相干科技等量子计算企业统一挂入
- 方案 B：暂时标记置信度降为 lowest，并在备注中说明差异

### 3. 光通信链：国科天迅 & 橙科微电子 → 驱动/TIA 存疑

**问题**：

| 企业 | 实际产品 | 挂载环节 | 偏差 |
|---|---|---|---|
| 北京国科天迅 | **光纤总线协议芯片**（FC-AE-1553 协议芯片） | 驱动/TIA芯片 | 协议芯片 ≠ 模拟驱动/TIA，技术路线完全不同 |
| 上海橙科微电子 | **高速网络通讯芯片/DSP类芯片** | 驱动/TIA芯片 | 网络DSP与光模块TIA/Driver是不同芯片类型 |

**当前状态**：两者均标记 `low` + `needs_review=true`，文档注释写"临时挂载待复核"。但这属于"无处可放才挂这里"而非"近似但不确定"——应该更明确地标注**临时占位**性质。

**建议**：将置信度提升为 `low` 不变，但依据摘要中加注"⚠️ 临时占位：非驱动/TIA芯片，待新建'光纤通信芯片'或'光通信DSP'环节后迁移"。

## 🔍 可优化（建议改进）

### 4. 上海不筹量子 (ENT_PG_35) 应在光计算链但未录入

**数据**：PostgreSQL id=35，核心技术"大规模原子量子计算系统模块化/工程化/集成化"，产品"量子计算基础设施、原子量子计算系统"。此前漏挂清单已建议挂光计算链。

**判断**：原子量子计算虽非纯光量子路线，但在当前光计算链覆盖量子计算方向的语境下，纳入比不纳入合理。

**建议**：若光计算链有意向覆盖量子计算方向，应补入；若严格限定光计算，则不纳入但需备注。

### 5. 光显示链：Micro LED 芯片 缺少西安中科微精光子

**数据**：西安中科微精光子 (ENT_PG_335) 产品含"光子芯片、光子器件、光子模块"，但未明确 Micro LED 方向。当前仅挂到光通信→硅光芯片。

**判断**：光子芯片方向若包含显示光子器件，可跨链挂载，但当前证据不足，留待后续评估。

### 6. 各链企业计数存在跨链重复

**说明**（非错误）：英伟芯在光通信(3条)和光计算(7条)同时计数，汇总时不应简单相加。当前文档按链独立统计是正确的做法，但读者容易误解总企业数 `21+20+22+11+11+15+27+20 = 147`（实际唯一企业约 120 家）。

**建议**：在汇总开头加一句总览："8 链合计涉及唯一企业约 120 家，挂载关系 219 条（含跨链重复计数）"。
