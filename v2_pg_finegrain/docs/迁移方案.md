# 迁移方案

## 1. 背景

当前工作区的旧版图谱主要基于 Excel/CSV 资产建设，现阶段底层数据源已切换为 PostgreSQL，同时业务人员反馈产业链粒度偏粗，需要支持更细层级的上下游、产品、器件、能力和企业挂接。

## 2. 核心策略

采用并行建设方式：

- `v1_pg_finegrain/`：保留旧版资产，作为历史基线和现有演示环境依据。
- `v2_pg_finegrain/`：承接 PostgreSQL 数据源、细粒度产业链模型和新版 Neo4j Docker。

旧环境不清库、不覆盖、不直接改导入脚本。

## 3. 新版数据流

```text
PostgreSQL
-> 抽取视图/SQL
-> 标准中间表 CSV
-> 校验与人工复核
-> Neo4j Docker 独立实例
-> 业务查询与验收
```

## 4. 为什么不直接同步 PostgreSQL 到 Neo4j

当前阶段优先采用离线导入，原因是：

- PostgreSQL 源表结构可能继续变化。
- 细粒度口径需要业务复核。
- CSV 中间表便于差异比对、版本管理和回滚。
- 不影响旧 Neo4j 服务。

## 5. 新 Neo4j 服务建议

建议使用独立 Docker Compose：

- Browser 端口：`7475`
- Bolt 端口：`7688`
- 数据卷：`neo4j_kg_v2_finegrain_data`
- 导入目录：`v2_pg_finegrain/neo4j/import`

## 6. 阶段推进

### 第一阶段：目录和口径初始化

- 完成旧版目录迁移。
- 建立新版目录。
- 建立产业链平级主数据。
- 以光通信/光模块构建细粒度样例。

### 第二阶段：PostgreSQL 抽取

- 明确企业、产品、技术、客户、行业、标签字段来源。
- 生成标准中间表。
- 对无法稳定判断的字段设为待复核。

### 第三阶段：Neo4j 验证

- 启动独立 Neo4j Docker。
- 导入产业链、环节、细分环节、企业挂接。
- 使用查询模板验证业务路径。

### 第四阶段：复制到其他平级产业链

光通信验证通过后，其他产业链按同一结构扩展，不再作为光通信的补充链处理。
