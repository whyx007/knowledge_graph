# 挂载方法论修正 — 应用场景挂载清理

生成日期：2026-07-01

## 原则

> **挂载依据 = 企业自身的核心技术 + 产品，不是客户/供应商/应用场景**

| 正确 ✅ | 错误 ❌ |
|---|---|
| 企业造激光焊接设备 → 挂"激光焊接设备" | 企业造激光焊接设备 → 挂"金属加工"（那是应用行业） |
| 企业造VCSEL芯片 → 挂"激光器芯片" | 企业造通用芯片 → 挂"航天电子单机"（那是应用场景） |
| 企业造3D视觉算法 → 挂"结构光3D视觉" | 企业造3D视觉算法 → 挂"汽车装配"（那是客户行业） |
| 企业运营遥感卫星 → 挂"遥感数据处理平台" | 企业做卫星测试 → 挂"商业运载火箭"（那是被测试对象） |

## ⚠️ 根治建议

当前的产业链设计本身混入了"下游应用行业层"（如金属加工、消费电子、汽车装配、半导体制造等），这导致挂载时容易按客户行业而非核心技术分类。根治方案：

1. **激光加工链**：删除 `金属加工` / `消费电子制造` / `半导体与精密制造` / `医疗器械与高端制造` 4个一级环节（它们不是产业链环节，是下游行业标签）
2. **机器人链**：删除 `汽车制造` / `半导体制造` / `医疗康养` / `商业服务与家庭场景` / `巡检安防与特种作业` 5个一级环节
3. 如有需要按行业筛选，应该用标签(Tag)而非产业链环节(stage/substage)
