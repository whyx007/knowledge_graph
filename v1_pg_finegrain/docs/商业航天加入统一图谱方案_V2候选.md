# 商业航天加入统一图谱方案（V2候选）

## 1. 目标
明确商业航天如何在不破坏当前统一图谱稳定性的前提下，加入统一图谱 V2。

---

## 2. 推荐加入方式
### 方案建议：候选域先行
不建议直接把商业航天写入当前正式主数据：
- `unified_subtracks.csv`
- `unified_chain_stages.csv`
- `unified_key_capabilities.csv`
- `unified_application_scenarios.csv`

建议先新增一套候选主数据文件，例如：
- `candidate_space_subtracks.csv`
- `candidate_space_chain_stages.csv`
- `candidate_space_key_capabilities.csv`
- `candidate_space_application_scenarios.csv`
- `candidate_space_tech_directions.csv`

等企业候选和映射验证完成后，再并入统一正式主数据。

---

## 3. 为什么不直接并入
### 3.1 当前三条样板链刚刚稳定
现有统一图谱已围绕：
- 光学检测 / 机器视觉
- 光通信 / 光模块
- 激光加工 / 光学装备

完成：
- 主数据
- 企业挂接
- 结构关系
- TechDirection
- KeyCapability / Capability / TechDirection 解释链

此时直接加入商业航天，容易引入新变量，影响当前样板链的稳定性。

### 3.2 商业航天与现有链存在交叉但不等同
例如：
- 激光通信终端
- 精密驱动/精指向机构
- 测运控平台

这些能力和现有链有交叉，但不能因此把商业航天简单拆散挂到现有链里。

### 3.3 商业航天的“域”属性更强
它更像一个新的产业方向，而不是当前某条子赛道的扩展应用场景。

---

## 4. 推荐的最小并入步骤
### 第一步：研究版与标准口径先落文件
已完成：
- `docs/商业航天产业链研究版.md`
- `design/商业航天图谱标准口径.md`

### 第二步：建立候选企业池
建议形成：
- `data/mappings/企业-商业航天映射表.csv`

目标：
- 先标“候选相关企业”
- 不急于导入正式主图谱

### 第三步：形成候选主数据 CSV
建议后续新增：
- `data/mappings/candidate_space_subtracks.csv`
- `data/mappings/candidate_space_chain_stages.csv`
- `data/mappings/candidate_space_key_capabilities.csv`
- `data/mappings/candidate_space_application_scenarios.csv`
- `data/mappings/candidate_space_tech_directions.csv`

### 第四步：做一次独立导入验证
先在 Neo4j 以候选 patch 方式验证，不直接污染当前正式统一图谱。

### 第五步：确认后再并入统一图谱 V2
待：
- 企业挂接稳定
- 结构关系稳定
- 查询模板可跑

再决定是否正式并入。

---

## 5. 当前建议的企业候选标准
纳入候选池的优先标准：
1. 与卫星/火箭/地面设备/卫星运营/卫星应用直接相关
2. 有明确产品或系统交付对象
3. 不是只和航天客户“间接相关”
4. 能在商业航天链中明确落主环节

---

## 6. 当前结论
商业航天现在最正确的加入方式不是“立刻并表”，而是：

> **先研究版 + 候选企业池 + 候选主数据 + 独立 patch 验证，再进入统一图谱 V2。**
