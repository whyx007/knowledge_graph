## 5. 当前导入顺序（已验证）
建议按以下顺序执行：

### 第一步：旧企业图谱已在库
前提：
- 旧企业图谱节点与关系已导入本地 Neo4j
- 当前 Enterprise 节点主键仍为旧 `ENT_xxx` 体系

### 第二步：执行统一 schema
执行：
- `neo4j/schema_unified_v1.cypher`

### 第三步：执行统一结构导入
执行：
- `neo4j/import_unified_v1.cypher`

这一步会导入：
- IndustryDomain / SubTrack / ChainStage / KeyCapability / ApplicationScenario
- HAS_SUB_TRACK / HAS_STAGE / UPSTREAM_OF / REQUIRES_CAPABILITY / DRIVES_STAGE
- 以及首版 `MAPPED_TO` 映射关系

### 第四步：如果 Enterprise 主键不一致，执行企业挂接补丁
如果当前库里的 Enterprise 主键还是旧 `ENT_xxx`，而不是 `E001` 体系，则需要额外执行：
- `neo4j/import_unified_enterprise_patch_legacyid.cypher`

这一步依赖：
- `unified_enterprise_id_mapping.csv`
- `*_legacyid.csv` 三张企业挂接关系表

### 第五步：执行验证脚本
执行：
- `neo4j/verify_unified_v1.cypher`

## 6. 本次真实导入时踩到的关键坑
### 6.1 Enterprise 主键体系不一致
这是本次最关键的问题。

现象：
- 统一关系表使用 `E001` 这种人工整理后的企业 ID
- 但本地 Neo4j Enterprise 节点仍使用旧 `ENT_xxx` 主键
- 结果：结构层全部导入成功，但企业挂接查询为空

解决方案：
- 新增 `unified_enterprise_id_mapping.csv`
- 基于映射表生成：
  - `unified_rel_enterprise_to_subtrack_legacyid.csv`
  - `unified_rel_enterprise_to_stage_legacyid.csv`
  - `unified_rel_enterprise_to_keycapability_legacyid.csv`
- 再执行 `import_unified_enterprise_patch_legacyid.cypher`

结论：

> 当前短期最稳的方案，是保留旧 Enterprise 主键，靠 mapping 层适配统一图谱挂接关系。

### 6.2 Neo4j Windows 启动方式
本地环境下：
- `neo4j.bat start` 不可用，因为未安装 Windows service
- `neo4j.bat console` 可启动，但在某些宿主环境下会被回收

实践上更稳的办法是：
- 以 detached 方式拉起 `neo4j.bat console`
- 确认 `localhost:7687` 可连后，再用 `cypher-shell` 执行导入
