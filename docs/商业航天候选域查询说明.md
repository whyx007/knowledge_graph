# 商业航天候选域查询说明

## 1. 目的
本说明对应：
- `neo4j/query_templates_candidate_space.cypher`

用途是把商业航天候选域从“已导入可验证”推进到“可演示、可评审”。

---

## 2. 当前最重要的查询原则
### 必须按候选域 ID 过滤
当前商业航天不是独立数据库，而是候选 patch 挂在同一张统一图上。
因此查询时必须带：
- `SUB_SPACE_001`
- `STG_SPACE_*`
- `KCAP_SPACE_*`
- `TD_SPACE_*`
- `ASCN_SPACE_*`

否则会混入：
- 原有光电子三条样板链关系
- 企业在正式主图谱中的既有关系

---

## 3. 当前支持的查询方向

### 3.1 候选域企业总览
适合回答：
- 当前商业航天候选域里有哪些企业？
- 每家企业在候选域里落在哪个环节、具备什么候选能力？

### 3.2 按环节找企业
适合回答：
- 某个商业航天环节是否已有候选企业？
- 候选企业分布在哪些环节？

### 3.3 看某企业在候选域中的位置
适合回答：
- 某家企业如果放到商业航天链里，应落在哪个主环节？
- 它在候选域里有哪些能力解释？

### 3.4 正式主链关系 vs 候选域关系对照
适合回答：
- 某家企业为什么会在查询里同时出现原正式链结果和商业航天候选结果？
- 候选域关系是否只是叠加，而不是覆盖原关系？

### 3.5 按关键能力找候选企业
适合回答：
- 商业航天候选能力现在有哪些企业可承接？

### 3.6 技术方向 / 应用场景驱动查询
适合回答：
- 当前商业航天候选域内部的技术方向、应用场景和环节之间是否已经成型？

---

## 4. 建议演示顺序
### 第一步：先看候选域企业总览
用于证明：
- 商业航天不是空壳结构
- 已经有企业挂接

### 第二步：再看按环节找企业
用于证明：
- 候选企业已经开始形成环节分布

### 第三步：再看某企业的对照查询
用于解释：
- 为什么企业会同时带着旧正式链与商业航天候选链关系
- 这不是错误，而是同一张统一图上的多域关系并存

### 第四步：最后看技术方向 / 应用场景驱动
用于证明：
- 商业航天候选域并不只是企业名单
- 结构层已经完整

---

## 5. 当前边界
当前商业航天候选域虽然已可查询，但仍有边界：
1. 企业数还少，仅适合原型验证与评审
2. 企业能力关系仍是候选口径，不代表正式并表结果
3. 尚未建立与旧 Capability / Scenario 的系统映射层
4. 尚未形成商业航天专用推荐模板

---

## 6. 一句话结论

> 商业航天现在已经可以被当成一个“候选独立域”来演示和评审，而不再只是结构层预留。
