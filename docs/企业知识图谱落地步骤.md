# 企业知识图谱落地步骤

## 1. 结论先说
你这份 `data/企业信息暂存.xlsx` 已经不是“空白原始数据”，而是一份可以直接作为**企业知识图谱第一版种子数据**的表。

原因很简单：它已经覆盖了企业图谱最核心的 4 类信息：
1. **企业主体信息**：公司名称、简介
2. **企业能力信息**：产品、技术、应用行业、应用场景、商业模式
3. **企业生态信息**：客户、供应商
4. **企业服务信息**：当前需求、营收融资、竞争优势、匹配度

所以现在最合理的做法不是先上复杂系统，而是：
**先把这张 Excel 拆成“实体 + 关系 + 属性”三层，形成企业知识图谱 MVP。**

---

## 2. 先明确：这次先建什么
本阶段先只建 **企业知识图谱**，不碰产业链图谱联动，不做自动抽取，不做复杂推理。

### 2.1 本期目标
把 Excel 里的企业信息整理成一个可查询、可扩展、可后续联动产业链图谱的企业知识图谱底座。

### 2.2 本期要做到的能力
至少支持这 5 个查询：
1. 查某家企业的完整画像
2. 按行业/应用领域找企业
3. 按产品/技术找企业
4. 按客户/供应商关系看企业生态
5. 按当前需求找需要服务的企业

---

## 3. 基于现有 Excel，建议抽成哪些节点
从你当前表结构看，建议先抽 8 类节点。

### 3.1 核心节点
1. **企业（Enterprise）**
2. **产品（Product）**
3. **技术/能力（Technology / Capability）**
4. **行业（Industry）**
5. **应用场景（Scenario）**
6. **客户（Customer）**
7. **供应商（Supplier）**
8. **需求标签（DemandTag）**

### 3.2 第二层可选节点
如果后面数据质量够，可以再补：
- 认证/知识产权（Certification / IP）
- 创始团队（FounderTeam）
- 融资阶段（FinancingStage）
- 营收规模（RevenueRange）
- 标签（Tag）

本期不建议一上来全做，否则清洗成本会很高。

---

## 4. 建议的关系设计

### 4.1 企业主关系
- 企业 -提供-> 产品
- 企业 -具备-> 技术/能力
- 企业 -服务于-> 行业
- 企业 -应用于-> 应用场景
- 企业 -拥有客户-> 客户
- 企业 -拥有供应商-> 供应商
- 企业 -存在需求-> 需求标签

### 4.2 企业属性（先不拆节点）
以下内容先挂在企业节点属性上，不急着拆实体：
- 公司简介
- 商业模式
- 认证/资质/知识产权
- 创始团队介绍
- 当前营收或融资情况
- 竞争优势/差异化
- 当前匹配度

这是最省事也最稳的做法。

## 5. 你的 Excel 字段怎么映射
虽然当前命令行里中文显示有点乱码，但字段语义已经能看出来。建议这样映射：

| Excel字段 | 图谱去向 | 建议处理 |
|---|---|---|
| 公司名称 | 企业节点主键/名称 | 必填，去重主键 |
| 一句话介绍/企业简介 | 企业属性 | 保留原文 |
| 产品 | 产品节点 + 企业-提供->产品 | 逗号/顿号拆分 |
| 客户 | 客户节点 + 企业-拥有客户->客户 | 多值拆分 |
| 供应商 | 供应商节点 + 企业-拥有供应商->供应商 | 多值拆分 |
| 核心能力/技术描述 | 技术/能力节点 + 企业-具备->能力 | 建议拆标签 |
| 产品应用行业 | 行业节点 + 企业-服务于->行业 | 多值拆分 |
| 应用场景 | 场景节点 + 企业-应用于->场景 | 多值拆分 |
| 细分应用场景/典型场景 | 场景节点 | 可并入应用场景 |
| 商业模式 | 企业属性 | 暂不拆图谱节点 |
| 竞争优势/壁垒/亮点 | 企业属性 | 暂不拆节点 |
| 认证/资质/知识产权 | 企业属性 | 后续可拆认证节点 |
| 创始团队/团队背景 | 企业属性 | 暂不拆节点 |
| 当前最需要资源/需求 | 需求标签节点 + 企业-存在需求->需求 | 必做 |
| 营收/融资/经营情况 | 企业属性 | 后续再规范化 |
| 企业核心竞争力/补充说明 | 企业属性 | 保留原文 |
| 匹配度 | 企业属性 | 用于后续筛选 |

## 6. 最小落地方案：先做三张表
不要一上来就想图数据库。先把数据整理成三张标准表，最稳。

### 6.1 表一：企业主表 enterprise_nodes
一行一家企业，保留企业属性。

建议字段：
- enterprise_id
- enterprise_name
- intro
- business_model
- certification_ip
- founder_team
- revenue_financing
- advantage
- match_level
- source_file

### 6.2 表二：实体表 entity_nodes
存“产品、行业、场景、客户、供应商、需求标签、能力标签”等标准化实体。

建议字段：
- entity_id
- entity_name
- entity_type
- normalized_name
- source

### 6.3 表三：关系表 graph_edges
存企业与其他实体的关系。

建议字段：
- from_id
- from_type
- relation_type
- to_id
- to_type
- raw_value
- confidence
- source

## 7. 真正实施时怎么做

### 第一步：先做字段清洗
重点做 4 件事：
1. **公司名称去重**：同一企业名称统一
2. **多值拆分**：把产品、客户、供应商、应用行业、场景、需求拆成多条
3. **空值处理**：空白、无、暂无、未披露统一处理
4. **分隔符统一**：逗号、顿号、分号、换行统一拆分

### 第二步：先做实体标准化
优先标准化以下 5 类：
- 产品
- 行业
- 应用场景
- 客户
- 需求标签

原因：这 5 类最影响查询效果。

### 第三步：生成关系表
以企业为中心，生成：
- 企业-产品
- 企业-行业
- 企业-场景
- 企业-客户
- 企业-供应商
- 企业-需求
- 企业-能力

### 第四步：先用表格或 CSV 验证
这一步非常重要。
先不要急着上 Neo4j、Nebula、GraphRAG。
先验证：
- 是否能查出企业画像
- 是否能按行业筛企业
- 是否能按需求筛企业
- 是否能看到客户/供应商生态

### 第五步：再决定落库方式
等这一步跑通后，再看用什么来承载：
- 如果偏展示与分析：可先用 Bitable / Sheets / CSV
- 如果偏关系查询：可上 Neo4j
- 如果偏后续大模型问答：再考虑 GraphRAG/向量检索联动

## 8. 推荐的本期 MVP 范围
### 必做
- 企业节点
- 产品节点
- 行业节点
- 场景节点
- 客户节点
- 供应商节点
- 需求标签节点
- 企业与上述节点关系

### 选做
- 技术/能力标签节点
- 认证/知识产权节点
- 融资事件节点

### 暂不做
- 自动 NLP 抽取
- 图算法推荐
- 大模型问答入口
- 产业链联动推理

---

## 9. 验收标准
企业知识图谱第一版完成，至少满足：

### 数据层
- 成功导入全部企业
- 企业名称已去重
- 产品/行业/场景/客户/供应商/需求完成拆分

### 图谱层
- 每家企业至少有 3 类以上关联关系
- 能形成企业画像卡片
- 能从任一行业/产品/需求反查相关企业

### 使用层
至少支持下面 3 个演示：
1. 输入企业名称，输出企业画像
2. 输入应用行业，返回相关企业
3. 输入资源需求，返回目标企业名单

---

## 10. 你现在最应该做的事
按优先级就是这 4 步：

1. **把 Excel 转成可清洗的标准表**
2. **做字段映射和多值拆分**
3. **产出 enterprise_nodes / entity_nodes / graph_edges 三张表**
4. **先验证查询，再决定是否上图数据库**

一句话说：
**先把企业知识图谱做成“结构化关系数据”，再谈图引擎。**
