# 投后产业服务知识图谱原型PRD

## 1. 背景
投后产业服务网站需要从“信息展示”升级为“知识驱动服务”，支撑企业识别、产业理解、资源匹配与服务推荐。现阶段不追求全量知识中台，而是先以原型方式落地两个最核心的图谱：企业图谱与产业链图谱。

## 2. 目标
在独立工作区内，沉淀一套可用于方案评审、原型演示、后续研发拆解的知识图谱定义。

具体目标：
1. 建立企业图谱原型
2. 建立产业链图谱原型
3. 打通双图谱的关键关联路径
4. 支撑若干高价值查询与推荐场景
5. 为后续投后服务能力扩展预留结构基础

## 3. 目标用户
### 3.1 内部用户
- 投后服务团队
- 投资经理 / 产业研究人员
- 运营人员
- 产品与研发团队

### 3.2 外部服务对象
- 被投企业
- 产业合作方
- 政府/园区/链主相关主体（后续可扩展）

## 4. 核心问题
当前信息可能分散在报告、企业库、行业资料、项目材料中，存在以下问题：
- 企业认知碎片化，难形成完整画像
- 产业链上下游关系难快速识别
- 难以从“企业需求”映射到“产业资源”
- 后续推荐、匹配、申报、协同等能力缺少统一知识底座

## 5. 本期范围（MVP）
### 5.1 本期只做两个图谱
#### A. 企业图谱
围绕“企业”构建多维画像与关联关系。

#### B. 产业链图谱
围绕“产业-环节-方向-能力-代表企业”构建产业链知识结构。

### 5.2 本期必须打通的关联
- 企业 -> 所属行业/赛道
- 企业 -> 所处产业链环节
- 企业 -> 产品/技术/能力
- 企业 -> 融资/投资/合作信息（可简化）
- 产业链环节 -> 代表企业
- 产业链环节 -> 上下游环节

### 5.3 暂不纳入本期
- 全量政策图谱
- 专利全文级图谱
- 人才图谱
- 事件流实时图谱
- 复杂自动推理引擎

## 6. 图谱设计
### 6.1 企业图谱
#### 核心实体
- 企业
- 企业标签
- 产品
- 技术
- 解决方案
- 行业/赛道
- 产业链环节
- 地区
- 融资事件
- 机构
- 需求
- 资源

#### 核心关系
- 企业-属于->行业/赛道
- 企业-位于->地区
- 企业-提供->产品
- 企业-掌握->技术
- 企业-具备->能力/解决方案
- 企业-处于->产业链环节
- 企业-发生->融资事件
- 融资事件-投资方->机构
- 企业-提出->需求
- 企业-可对接->资源
- 企业-关联->企业标签

#### 典型用途
- 查看单家企业全景画像
- 找到某类企业的能力分布
- 基于需求定位潜在合作企业
- 支撑投后企业服务档案

### 6.2 产业链图谱
#### 核心实体
- 产业
- 子产业/赛道
- 产业链环节
- 上游材料/零部件
- 中游模块/系统
- 下游应用场景
- 技术方向
- 关键能力
- 代表企业

#### 核心关系
- 产业-包含->子产业/赛道
- 子产业/赛道-包含->产业链环节
- 产业链环节-上游依赖->产业链环节
- 产业链环节-下游流向->产业链环节
- 产业链环节-需要->关键能力
- 技术方向-支撑->产业链环节
- 产业链环节-代表企业->企业
- 应用场景-拉动->产业链环节

#### 典型用途
- 快速理解某产业链结构
- 找上下游协同企业
- 找某环节缺口和可补能力
- 支撑产业研究与链式推荐

### 6.3 双图谱联动逻辑
双图谱的关键连接点：
- 企业 <-处于-> 产业链环节
- 企业 <-属于-> 行业/赛道
- 企业 <-具备-> 技术/能力
- 产业链环节 <-需要-> 技术/能力

通过上述连接，可以完成：
- 从企业出发看其产业位置
- 从产业链环节出发找相关企业
- 从企业需求出发找产业资源与潜在对接方

## 7. 业务场景
### 场景1：企业画像查询
输入企业名称，输出：基础信息、所属赛道、产业链环节、产品技术、融资信息、需求标签、协同机会。

### 场景2：产业链位置识别
输入企业名称，输出其所在产业、上下游位置、相邻环节、潜在合作对象。

### 场景3：按环节找企业
输入某产业链环节，输出代表企业、被投企业、技术能力覆盖情况。

### 场景4：按需求找资源
输入企业需求标签，输出可匹配的产业链环节、潜在服务资源、相关企业。

### 场景5：领导演示视图
展示“一个企业如何挂到一条产业链上，并找到上下游与协同资源”。

## 8. 数据源建议
### 8.1 企业图谱数据源
- 被投企业名录
- 企业介绍/BP/官网摘要
- 融资信息
- 行业分类标签
- 内部投后服务记录
- 手工标注的需求/能力标签

### 8.2 产业链图谱数据源
- 产业研究报告
- 行业公开资料
- 产业链环节梳理文档
- 专家访谈整理
- 现有汇报/PPT中的产业链结构材料

### 8.3 原型阶段数据策略
采用“小样本高质量”策略：
- 选 1-2 条重点产业链
- 每条产业链先覆盖 20-50 家企业样本
- 每家企业只保留关键字段与关键关系

## 9. 交付物
本工作区建议沉淀以下交付物：
1. 知识图谱原型PRD
2. 双图谱实体关系清单
3. 数据源清单
4. 样例数据文件
5. 演示脚本
6. 后续研发需求清单

## 10. 验收标准
### 10.1 结构验收
- 已定义企业图谱实体和关系
- 已定义产业链图谱实体和关系
- 已定义双图谱连接关系

### 10.2 数据验收
- 至少沉淀一批样例企业数据
- 至少沉淀一条产业链样例结构
- 样例数据可支撑 3 个以上演示查询

### 10.3 场景验收
至少能演示以下能力：
1. 查一个企业的画像
2. 看一个企业所处产业链位置
3. 按产业链环节找企业
4. 从需求标签找潜在协同对象

## 11. 风险与约束
- 企业标签标准不统一，可能影响映射准确性
- 产业链环节划分口径可能存在多版本
- 原始资料质量参差不齐，需要人工校准
- 原型阶段不宜追求自动化全覆盖

## 12. 下一步建议
1. 从既有《投后产业服务知识图谱构建方案》中抽取可复用内容
2. 先选定一个重点产业方向作为样板
3. 形成企业样例表 + 产业链环节表
4. 明确演示路径与页面原型
