# 产业链图谱最小模型

> **状态说明（2026-05-03 更新）**
> 本文件是早期的**图谱建模骨架稿**，用于快速讨论节点、关系、挂接方式。
> 它**不是**基于系统性外部研究资料校准后的“客观产业链事实版”，因此：
> - 可作为图谱结构讨论草稿
> - **不可直接作为产业研究结论或实际产业链现状依据**
>
> 后续应以“研究版产业链文档”为准，再反推图谱模型。

## 1. 目标
本模型用于支撑投后产业服务知识图谱的第二张图谱——产业链图谱。

设计原则：
- 先做最小可用，不追求大而全
- 先围绕 3 个小产业链打样
- 先支持“查询、演示、连接企业图谱”三类核心目标
- 结构尽量统一，便于后续扩展更多产业方向

当前优先样板方向：
1. 光学检测 / 机器视觉
2. 光通信 / 光模块
3. 激光加工 / 光学装备

---

## 2. 适用场景
本模型至少要支撑以下场景：
1. 快速理解某一小产业链结构
2. 看某企业处于哪个产业方向、哪个链条环节
3. 从某个产业链环节反查相关企业
4. 从企业能力反推可承接哪些产业链环节
5. 为后续上下游协同推荐提供基础结构

---

## 3. 最小实体集

### 3.1 Industry（产业）
用于表达较大的产业主题。

建议示例：
- 光电子
- 智能制造（可选上位产业）

建议字段：
- industry_id
- industry_name
- description
- source

---

### 3.2 SubTrack（子赛道）
用于表达本次真正落图谱的业务方向。

本期固定 3 个样板子赛道：
- 光学检测 / 机器视觉
- 光通信 / 光模块
- 激光加工 / 光学装备

建议字段：
- sub_track_id
- sub_track_name
- industry_name
- description
- priority
- source

说明：
本期很多查询会直接以子赛道作为入口，因此 SubTrack 是核心节点，不是附属字段。

---

### 3.3 ChainStage（产业链环节）
用于表达某子赛道内部的产业链位置。

示例：
- 上游光学元件
- 上游核心器件
- 中游模组/设备
- 中游系统集成
- 下游行业应用

建议字段：
- stage_id
- stage_name
- stage_level（上游/中游/下游）
- stage_category
- description
- source

说明：
本期 ChainStage 是产业链图谱中最重要的结构节点，后续企业图谱也主要通过它实现挂接。

---

### 3.4 TechDirection（技术方向）
用于表达支撑某环节的关键技术方向。

示例：
- 图像采集
- 图像处理算法
- 光学设计
- 高速调制
- 精密振镜控制
- 激光器控制

建议字段：
- tech_id
- tech_name
- description
- source

---

### 3.5 KeyCapability（关键能力）
用于表达企业或环节需要具备的能力标签。

示例：
- 缺陷检测算法能力
- 光学系统集成能力
- 高速封装测试能力
- 激光加工工艺调优能力

建议字段：
- capability_id
- capability_name
- description
- source

说明：
KeyCapability 是企业图谱和产业链图谱最重要的连接点之一。

---

### 3.6 ApplicationScenario（应用场景）
用于表达产业链最终服务的应用侧场景。

示例：
- 消费电子检测
- 半导体检测
- 数据中心互联
- 5G承载网络
- 汽车零部件加工
- 锂电制造

建议字段：
- scenario_id
- scenario_name
- description
- source

---

### 3.7 RepresentativeEnterprise（代表企业）
本期不建议单独新建一套“代表企业库”，而是优先复用企业图谱中的 `Enterprise` 节点。

因此在产业链图谱里：
- 不单独维护重复企业节点
- 直接通过 `Enterprise` 节点承担“代表企业”角色

这意味着：
- 产业链图谱负责定义结构
- 企业图谱负责沉淀企业属性与业务标签
- 双图谱通过关系连接，不重复造节点

---

## 4. 最小关系集

### 4.1 Industry -[:HAS_SUB_TRACK]-> SubTrack
表示产业包含某子赛道。

示例：
- 光电子 -> 光学检测 / 机器视觉
- 光电子 -> 光通信 / 光模块
- 光电子 -> 激光加工 / 光学装备

---

### 4.2 SubTrack -[:HAS_STAGE]-> ChainStage
表示某子赛道包含哪些产业链环节。

说明：
建议每个子赛道至少沉淀 5~8 个最关键环节，不要一开始拆得过细。

---

### 4.3 ChainStage -[:UPSTREAM_OF]-> ChainStage
表示环节间的上游到下游关系。

说明：
这是产业链“链条感”的核心关系。

---

### 4.4 TechDirection -[:ENABLES_STAGE]-> ChainStage
表示某技术方向支撑某产业链环节。

---

### 4.5 ChainStage -[:REQUIRES_CAPABILITY]-> KeyCapability
表示某环节需要哪些关键能力。

---

### 4.6 ApplicationScenario -[:DRIVES_STAGE]-> ChainStage
表示某应用场景拉动某环节需求。

---

### 4.7 Enterprise -[:LOCATED_IN_STAGE]-> ChainStage
表示某企业处于某产业链环节。

说明：
这是双图谱最重要的连接关系。

---

### 4.8 Enterprise -[:FOCUSES_ON_SUB_TRACK]-> SubTrack
表示某企业聚焦于某个子赛道。

说明：
如果企业已经能明确落在某个 3 个样板方向之一，建议直接建立该关系。

---

### 4.9 Enterprise -[:HAS_CAPABILITY]-> KeyCapability
说明：
如果企业图谱中已有 Capability，可分两步处理：
1. 短期：沿用现有 Capability 节点
2. 中期：将产业链关键能力与企业能力做标准映射

本期为了快速落地，建议：
- 允许企业图谱的 Capability 与产业链图谱的 KeyCapability 暂时并存
- 在双图谱打通方案中补充“能力标准映射层”

---

## 5. 三个样板子赛道建议口径

### 5.1 光学检测 / 机器视觉
建议优先结构：
- 上游：光源 / 镜头 / 相机 / 传感器
- 中游：采集模组 / 算法平台 / 检测设备 / 系统集成
- 下游：消费电子 / 半导体 / 面板 / 锂电 / 汽车制造检测

重点技术方向：
- 图像采集
- 图像处理
- 缺陷检测算法
- 光学成像
- 精密运动控制

---

### 5.2 光通信 / 光模块
建议优先结构：
- 上游：芯片 / 激光器 / 探测器 / 光器件 / 材料
- 中游：光引擎 / 光模块封装 / 测试设备
- 下游：数据中心 / 电信网络 / AI算力互联

重点技术方向：
- 高速调制
- 光电转换
- 封装测试
- 热管理
- 高速互连

---

### 5.3 激光加工 / 光学装备
建议优先结构：
- 上游：激光器 / 光学器件 / 控制器 / 振镜 / 机械平台
- 中游：激光加工设备 / 光学装备系统 / 自动化集成
- 下游：金属加工 / 消费电子制造 / 锂电 / 光伏 / 汽车零部件

重点技术方向：
- 激光控制
- 振镜控制
- 精密加工工艺
- 运动控制
- 装备集成

---

## 6. 粒度控制原则
为了避免第一版失控，本期粒度建议如下：

### 必做
- 产业
- 子赛道
- 产业链环节
- 技术方向
- 关键能力
- 应用场景
- 企业与环节/子赛道连接

### 选做
- 典型产品
- 上游材料细分
- 区域集群
- 产业短板/卡点

### 暂不做
- 全量专利技术树
- 复杂工艺参数库
- 动态市场规模指标体系
- 自动推理规则库

---

## 7. 建模建议

### 7.1 命名建议
为避免后续混乱，建议统一：
- 产业：较大方向，如“光电子”
- 子赛道：本次业务建模重点，如“光通信 / 光模块”
- 产业链环节：链条位置，如“光模块封装测试”
- 技术方向：技术主题，如“高速调制”
- 关键能力：可由企业承接的能力，如“高速封装测试能力”
- 应用场景：下游需求场景，如“数据中心互联”

### 7.2 编码建议
建议后续样例数据中使用如下前缀：
- IND_：产业
- SUB_：子赛道
- STG_：环节
- TEC_：技术方向
- CAP_：关键能力
- SCN_：应用场景

---

## 8. 本期验收标准
最小模型设计完成后，至少满足：
1. 能完整描述 3 个小产业链的主干结构
2. 每个子赛道至少有一组可串起来的上下游环节
3. 每个子赛道至少定义若干技术方向、关键能力、应用场景
4. 企业图谱可通过“子赛道/环节/能力”挂接到产业链图谱
5. 可支持后续 3 个以上演示查询
